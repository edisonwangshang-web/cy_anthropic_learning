# 项目上下文

## 受众

主要用户是没有编程背景、但希望借助 AI 完成真实产品的人。他们通常：

- 能使用浏览器和常见办公软件。
- 不熟悉代码结构、命令行、数据库和部署。
- 容易把“页面能打开”误认为“产品已经完成”。
- 遇到英文长文、抽象术语和报错时容易中断学习。
- 需要明确的下一步、完成示例和可检查产出。

## 课程目标

学员最终应能在 AI 辅助下：

1. 把模糊产品想法写成规格和验收标准。
2. 理解客户端、后端、数据库、API 和部署的数据流。
3. 管理长项目的功能清单、进度、测试和发布。
4. 判断权限、安全、数据、成本和供应商风险。
5. 要求 AI 提供测试、日志和数据证据。
6. 上线后执行监控、故障排查、备份和回滚。

## 当前交付边界

- `Anthropic工程博客学习路径课程.html` 是六阶段工程判断先修课，负责规格、上下文、工具、安全、评测和故障复盘能力。
- `AI时代非程序员全栈产品课程大纲.md` 是正式产品课框架，负责把判断力落到真实数据库、后端、客户端、权限、部署和运维。
- 先修课可以给学员一套工程判断包，但不能宣称学员已经完成生产可用产品。

## 课程不追求

- 背诵编程语法和框架 API。
- 手写标准算法作为主要成绩。
- 只做没有真实数据、权限和运维要求的 Demo。
- 让某一种 AI IDE 或低代码工具成为不可替换的课程本体。

## 当前贯穿案例

页面推荐使用预约、工单、记账或库存平台作为贯穿项目。示例优先使用“带用户和权限的预约平台”，因为它能自然覆盖：

- 注册登录和多用户数据隔离。
- 列表、表单、状态和异常反馈。
- 数据库关系和业务约束。
- 通知、第三方服务和失败重试。
- 部署、日志、监控、备份和回滚。

## 内容来源

- Anthropic Engineering 文章全文归档及原文。
- 基于全文整理的非官方中文精读摘要；它不是逐段或完整翻译，完整证据需要回到英文原文。
- 在线学习产品的公开课程设计说明。
- 项目课程大纲中的生产可用标准。

来源负责提供证据，课程页面负责把证据转化为学习动作和项目产出。
